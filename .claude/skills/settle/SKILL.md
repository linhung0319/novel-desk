# 定案

作者要把剛才討論的結論寫進正式區。你負責整理、檢查、給作者看，作者確認後才寫。不替作者補劇情，也不順手改別的東西。

作者補充：$ARGUMENTS

## 1. 定範圍

從作者補充和剛才的對話判斷要定案什麼。判斷不了，或對話裡有幾種說法還沒收斂，就問作者。缺書名時，`books/` 只有一本就用那本，否則問作者。

| 內容 | 寫到 |
|---|---|
| 角色 | `cards/characters/<名>.md` |
| 世界觀、地點、道具 | `cards/world/<主題>.md` |
| 水下清單：讀者還不知道的事，在哪個場景揭曉、伏筆埋在哪些場景 | `cards/hidden/<名>.md` |
| 主線、題旨、結局、基調 | `摘要.md` |
| 大綱：全書的總綱，或一個故事弧的大綱 | `outline/總綱.md`、`outline/arcNN.md` |
| 場景表：一個故事弧拆成的場景 | `scenes/arcNN.md` |

一次定案可能要寫好幾處，例如場景表裡出現新角色。逐一列出。不寫 `notes/`、`chapters/`、`drafts/`。

## 2. 整理

- 只寫結論，不寫討論過程和被否決的方案。那些屬於 `notes/`，作者要記才記。
- 檔案已經存在時先讀，只改這次定案的部分，其他照抄。和舊內容矛盾時列出來問作者，不要自己選。
- 卡片開頭照 README 寫別名。
- 場景表每個場景一個小標題，寫誰想要什麼、發生什麼、結尾處境變成什麼。作者想好的畫面或寫法理由，順手記在場景旁。作者沒談到的不要補，留給第 3 步問。

**水下：** 真相照作者說的寫，寫在哪個檔都可以，不要拆成現象，也不要另給一個拆過的版本。`cards/hidden/` 是清單，寫法見 README 的「水下」；`/draft` 和 `/passage` 靠它知道哪些事讀者還不知道。你要顧的是清單和這次定案的內容對得上：

- 這次的內容裡有讀者還不知道的事，清單上卻沒有：列出來，問作者要不要加一條。哪些算水下由作者決定。
- 場景表裡有一場揭曉了清單上的事：問作者要不要把那一條的「揭曉」填成這一場。作者說某場是替哪件事埋伏筆時，記進那一條的「伏筆」。
- 揭曉和伏筆只記故事弧和場景的小標題，不記章號。這次改了場景的小標題，或刪了、搬了場景，清單上提到它的地方一起改。
- 揭曉之後條目留著，不刪，也不用把卡片改寫一遍。
- 作者沒說在哪裡揭曉就留空，不要自己排。

## 3. 檢查

照寫到哪，讀對應的清單，逐條看這次要寫的內容：

| 寫到 | 讀 |
|---|---|
| `outline/`（總綱也算） | `knowledge/checks/故事弧.md` |
| `scenes/` | `knowledge/checks/場景.md` |
| 角色、世界觀、`摘要.md`、`cards/hidden/` | 沒有清單 |

寫場景表時，同一個故事弧裡已有的場景也要讀，才看得出接不接得上、高低在哪；也讀這個故事弧的大綱，場景沒交出大綱寫的結尾、轉折時，列在「對不上」。寫故事弧大綱時，讀總綱和前後故事弧的大綱。

不管寫到哪，都要查和既有內容有沒有矛盾，也讀 `cards/hidden/` 對一次清單。

## 4. 給作者看

- **要寫的檔：** 路徑；新檔給全文，舊檔給改了哪些地方。
- **檢查結果：** 照清單的寫法，只列有問題的。每一項先說你在作者的內容裡看到什麼，再說缺了什麼，最後才問；作者不用回頭翻場景表就看得懂你在問哪裡。沒有問題就寫一句「某某清單沒有問題」。
- **水下清單：** 建議新增的條目、要填的揭曉場景或伏筆、要跟著改的場景名，各引這次內容裡的原句。清單的改動也列在「要寫的檔」。沒有就不寫這項。
- **你補的東西：** 對話裡沒談到、你自己補上的字句。
- **對不上：** 和既有卡片、大綱、場景表矛盾的地方。只列矛盾；缺的東西不列，除非是大綱寫了、場景表沒交出。

等作者說可以才寫。作者要改就照改。作者說照寫，就照寫，不再追問檢查的問題。

## 5. 寫入

寫完回報寫了哪些檔。不回頭改 `notes/`，兩邊不同步。
