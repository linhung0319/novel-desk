# 定案

作者要把剛才討論的結論寫進正式區。你負責整理、檢查、給作者看，作者確認後才寫。不替作者補劇情，也不順手改別的東西。

作者補充：$ARGUMENTS

## 1. 定範圍

從作者補充和剛才的對話判斷要定案什麼。判斷不了，或對話裡有幾種說法還沒收斂，就問作者。缺書名時，`books/` 只有一本就用那本，否則問作者。

| 內容 | 寫到 |
|---|---|
| 角色 | `cards/characters/<名>.md` |
| 世界觀、地點、道具 | `cards/world/<主題>.md` |
| 還沒揭露、AI 提前知道就可能寫壞的真相 | `cards/hidden/<名>.md` |
| 主線、題旨、結局、基調 | `摘要.md` |
| 大綱：全書的總綱，或一個故事弧的大綱 | `outline/總綱.md`、`outline/arcNN.md` |
| 場景表：一個故事弧拆成的場景 | `scenes/arcNN.md` |

一次定案可能要寫好幾處，例如場景表裡出現新角色。逐一列出。不寫 `notes/`、`chapters/`、`drafts/`。

## 2. 整理

- 只寫結論，不寫討論過程和被否決的方案。那些屬於 `notes/`，作者要記才記。
- 檔案已經存在時先讀，只改這次定案的部分，其他照抄。和舊內容矛盾時列出來問作者，不要自己選。
- 卡片開頭照 README 寫別名。
- 場景表每個場景一個小標題，寫誰想要什麼、發生什麼、結尾處境變成什麼。作者想好的畫面或寫法理由，順手記在場景旁。作者沒談到的不要補，留給第 3 步問。

**水下：** 除了 `cards/hidden/`，正式區的檔都會被 `/draft` 讀進寫手的 prompt，包括 `摘要.md` 的結局。所以：

- 還沒揭露的真相，在其他檔只寫讀者會看到的現象和外在行為，原因、真實身分、幕後安排寫進 `cards/hidden/<名>.md`。
- 哪些算水下由作者決定。你只把看起來是的句子列出來，建議怎麼拆。
- 這次定案的是揭曉：真相併進公開的卡片或大綱，再問作者要不要刪掉 `cards/hidden/` 裡那支檔。真相已揭給讀者、只有主角不知道時，也移回公開的檔，並註明主角還不知道。

## 3. 檢查

照寫到哪，讀對應的清單，逐條看這次要寫的內容：

| 寫到 | 讀 |
|---|---|
| `outline/`（總綱也算） | `knowledge/checks/故事弧.md` |
| `scenes/` | `knowledge/checks/場景.md` |
| 角色、世界觀、`摘要.md`、`cards/hidden/` | 沒有清單 |

寫場景表時，同一個故事弧裡已有的場景也要讀，才看得出接不接得上、高低在哪。寫故事弧大綱時，讀總綱和前後故事弧的大綱。

不管寫到哪，都要查兩件事：和既有內容有沒有矛盾、有沒有水下該分出去。

## 4. 給作者看

- **要寫的檔：** 路徑；新檔給全文，舊檔給改了哪些地方。
- **檢查結果：** 照清單的寫法，只列有問題的。沒有問題就寫一句「某某清單沒有問題」。
- **建議移到水下的句子：** 原句、你建議留在原檔的寫法、移到哪支 `cards/hidden/`。沒有就不寫這項。
- **你補的東西：** 對話裡沒談到、你自己補上的字句。
- **對不上：** 和既有卡片、大綱、場景表矛盾的地方。

等作者說可以才寫。作者要改就照改。作者說照寫，就照寫，不再追問檢查的問題。

## 5. 寫入

寫完回報寫了哪些檔。不回頭改 `notes/`，兩邊不同步。
